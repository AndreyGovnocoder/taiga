# Рантайм-чеклист Taiga (ручная проверка на устройстве/симуляторе)

> Этот документ — для проверки приложения **руками** на Mac (симулятор и/или реальный телефон). Claude на Windows проверяет код только статически (чтением); поведение запущенного приложения подтверждается здесь.

## Что это и зачем

«Рантайм» = приложение реально запущено и вы им пользуетесь. Рантайм-чеклист — список действий «нажми X → должно произойти Y». «Скомпилировалось без ошибок» НЕ означает «работает правильно»: компилятор ловит ошибки в коде, но не ловит логические баги поведения (кнопка нажимается, а чат не исчезает; спиннер крутится вечно; счётчик непрочитанных не сбрасывается). Эти вещи видны только при запуске — поэтому после каждой сборки на Mac имеет смысл пройти релевантную часть этого чеклиста.

Граница машин: Claude пишет Swift на Windows и пушит в GitHub → вы делаете `git pull` на Mac, собираете в Xcode, запускаете, проходите чеклист. «Git = граница между машинами».

## Как пользоваться

1. На Mac: `git pull`, открыть проект `MyMessanger` в Xcode, запустить (⌘R) на симуляторе и/или телефоне.
2. Идти по нужному разделу сверху вниз, выполнять «Действие» и сверять с «Ожидается».
3. **Держать открытой консоль Xcode** (View → Debug Area → Activate Console, или ⇧⌘Y). Там видны `print(...)`-логи приложения (многие начинаются с `СЕРВЕР:`). При любом странном поведении эти логи — главная улика.
4. Прошёл пункт → отметить `[x]`. Не прошёл → это **фейл**: см. раздел «Как сообщать о фейле» внизу.

## Подготовка к проверке

- **Два тестовых аккаунта** (назовём A и B) — нужны для проверки переписки, RLS, блокировок. Удобно: A на реальном телефоне, B на симуляторе (или два симулятора).
- Знать, **какой аккаунт где** залогинен — это важно для диагностики (особенно текущего бага со списком чатов).
- Если проверяете «с нуля» — удалить приложение с устройства перед установкой, чтобы локальная БД (SwiftData) и кэш были чистыми.
- Сеть включена (Wi-Fi/сотовая); для проверок реконнекта понадобится переключать режим полёта.

## 0. Сборка и запуск (база)

- [ ] Проект собирается в Xcode без ошибок (⌘B).
- [ ] Приложение запускается на симуляторе (⌘R) и на реальном телефоне.
- [ ] Новые файлы (`BlockedUsersView`, `EULAAcceptanceView`, `LegalTexts`, и пр.) подхватились автоматически (Xcode 16 синхронизирует группы — править `.pbxproj` не нужно). Если файл «не виден» — сказать Claude.

## 1. Список чатов (ТЕКУЩИЙ БАГ — приоритет)

- [ ] При входе список чатов загружается; внизу индикатор «Обновление...» **сменяется** на «Синхронизировано» в течение ~1–3 сек.
- [ ] Индикатор «Обновление...» **НЕ висит бесконечно**. ← сейчас фейлит на эмуляторе.
- [ ] Pull-to-refresh (потянуть список вниз) обновляет и завершается (не зависает).
- [ ] При пустом списке показывается «У вас в Тайге нет чатов» (а не вечный спиннер).
- [ ] При реальной ошибке сети — оверлей «Ошибка загрузки» с кнопкой «Повторить» (а не молчаливый спиннер).

> Если «Обновление...» висит: в консоли Xcode скопировать ВСЕ строки за ~10 секунд после открытия списка (особенно с `СЕРВЕР:`, `подписк`, `Обновляем`) и прислать Claude. Это решающая улика.

## 2. Отправка и получение сообщений (realtime)

- [ ] A пишет B → у B сообщение появляется **без ручного обновления** (realtime).
- [ ] B отвечает → у A появляется без обновления.
- [ ] Свернуть приложение у B на 1–2 мин, A пишет → при возврате B сообщение появляется (реконнект подписки).
- [ ] Режим полёта у B вкл→выкл во время диалога → после возврата сети сообщения догружаются, дубликатов нет.
- [ ] Отправка при выключенной сети → сообщение помечается как неотправленное; после возврата сети уходит один раз (не дублируется).

## 3. UGC-модерация: блокировки и жалобы

- [ ] **Блок из 1:1-чата:** A открывает чат с B → меню → «Заблокировать» → подтверждение (confirmationDialog) → чат с B исчезает из списка, сообщения B не приходят.
- [ ] **Блок из группы:** в группе тап по сообщению участника → «Заблокировать» → его сообщения в группе скрываются.
- [ ] **Блок из контактов:** в списке контактов заблокировать → контакт исчезает из выдачи поиска/контактов.
- [ ] **Жалоба:** тап «Пожаловаться» на сообщение/чат/группу/контакт → один тап → алерт «Жалоба отправлена».
- [ ] **`BlockedUsersView`:** в настройках открыть список заблокированных → там виден B → «Разблокировать» → B пропадает из списка, его чат/сообщения снова доступны.
- [ ] После блокировки и перезапуска приложения блок сохраняется (персистентность `blockedUserIds`).
- [ ] После выхода из аккаунта (logout) и входа под другим — список блоков сбрасывается/перезагружается под нового юзера.

## 4. EULA-гейт (согласие с правилами)

- [ ] **Регистрация:** новый пользователь не может зарегистрироваться без включённого тоггла согласия с EULA.
- [ ] **Уже вошедший без согласия:** показывается `fullScreenCover` с EULA, который нельзя обойти, пока не принял.
- [ ] Экран «О приложении» показывает тексты из `LegalTexts` (включая UGC-раздел).
- [ ] После выхода из аккаунта согласие EULA сбрасывается (при следующем входе спрашивается снова, если так задумано).

## 5. Непрочитанные / бейджи (unread)

- [ ] Пришло сообщение в чат → счётчик непрочитанных у чата и в табах («Все»/«Личные»/«Группы») увеличивается.
- [ ] Открыл чат и прочитал → счётчик этого чата обнуляется (`mark_chat_read`), бейджи в табах пересчитываются.
- [ ] **Muted-чат:** замьюченный чат с новыми сообщениями НЕ добавляется в счётчик табов (проверка `!isMuted`).
- [ ] Счётчик согласован после перезапуска (сервер — источник истины через `last_read_at`).

## 6. RLS на двух аккаунтах (доступ к данным)

- [ ] A видит только свои чаты/сообщения/группы; чужие приватные чаты не видны.
- [ ] Аватары и медиа A грузятся; B не может подменить/удалить файл A (проверка владельца в Storage).
- [ ] Профиль: A видит профиль B (имя/аватар) в общих чатах, но не может его изменить.
- [ ] Никаких «пустых» зависаний из-за отказа доступа — отказ должен давать понятную ошибку, а не вечный спиннер.

## 7. Удаление аккаунта (server-first)

- [ ] Настройки → удалить аккаунт → подтверждение → аккаунт удаляется на сервере ПЕРЕД очисткой локального кэша.
- [ ] После удаления: повторный вход под этим аккаунтом невозможен; его файлы в Storage (аватары) исчезли; у собеседника он пропадает из контактов.
- [ ] Локальный кэш не остаётся «зомби» (не показывает удалённый аккаунт как активный).

## 8. Storage после ужесточения политик

- [ ] Загрузка своего аватара — работает (200).
- [ ] Загрузка медиа в чат — работает.
- [ ] Просмотр чужих аватаров/медиа (публичное чтение) — работает.
- [ ] Чужой пользователь НЕ может удалить/перезаписать ваш файл (это уже закрыто на сервере, проверяется поведением: чужой аватар не пропадает).

## Как сообщать о фейле

Чтобы Claude починил быстро и с первого раза, на каждый непрошедший пункт прислать:

1. **Что делали** — конкретные шаги (какой экран, что нажали, под каким аккаунтом A/B).
2. **Что ожидали** и **что произошло** на самом деле.
3. **Где** — симулятор или реальный телефон (и какая модель iOS, если знаете).
4. **Лог из консоли Xcode** — выделить и скопировать строки за время воспроизведения бага (особенно `СЕРВЕР:`, ошибки, стек-трейсы). Это самое ценное: для непроверяемого на Windows кода лог из рантайма заменяет мне отладчик.
5. Если падение (краш) — приложить текст из вкладки с трассировкой/исключением.

> Любой фейл чиним **в первую очередь**, до новых фич.
